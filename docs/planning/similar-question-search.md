# F4 유사 질문 검색 — 설계 근거

## 결정

- 한국어 문장 임베딩(SBERT, `jhgan/ko-sroberta-multitask`)을 **빌드 타임에 미리 계산**해
  `static/data/embeddings.json`에 저장하고, 프론트는 이 정적 JSON을 fetch해 코사인
  유사도만 계산한다. **런타임에 임베딩 모델을 로딩하지 않는다.**
- 검색 결과에 LLM이 생성한 답변을 쓰지 않고, 이미 축적된 실제 질문·답변(`q`/`a`) 원문을
  그대로 반환한다.
- 임계값으로 결과를 잘라내지 않고 **항상 top-3를 노출**하되, 1위 점수 구간에 따라
  안내 문구만 3단계로 달리 표시한다 (`≥0.7` "비슷한 질문을 찾았습니다",
  `≥0.45` "관련 있을 수 있는 질문입니다", 그 아래 "정확히 일치하는 질문은 없지만,
  가까운 기록입니다").
- 유사도 정렬 후 **같은 intent는 최고점 1건만 남기고** 다음 순위 후보로 top-3를 채운다
  (`questions.js`의 `searchSimilar`).

## 이유

1. **데모 안정성** — 해커톤/데모 환경에서 매 요청마다 임베딩 모델을 로딩하거나 외부
   임베딩 API를 호출하면 응답 지연·실패 지점이 늘어난다. 사전 계산된 벡터를 정적
   파일로 서빙하면 프론트 fetch + 벡터 연산만으로 완결되어, 네트워크/모델 서버 상태와
   무관하게 항상 같은 결과를 안정적으로 보여줄 수 있다.
2. **환각 없음, 출처 추적 가능** — 검색 결과가 LLM이 새로 생성한 텍스트가 아니라
   실제로 누군가 남긴 질문·답변이므로, 잘못된 정보를 지어내는(hallucination) 문제가
   구조적으로 없다. 각 결과에 작성자·부서·날짜가 그대로 따라오므로 "누가 언제 답한
   내용인지" 바로 추적할 수 있다.
3. **단일 임계값으로 분리 불가** — 시드 데이터로 측정한 재현율(관련 질문을 실제로
   잡아내는 비율) 최저 0.300, 오탐(관련 없는 질문의 최고 유사도) 최고 0.730 구간이
   겹쳐, "이 점수 이상만 보여준다"는 단일 컷오프로는 관련 있는 질문을 놓치거나
   관련 없는 질문을 섞어 보여주는 것을 동시에 피할 수 없었다. 그래서 컷오프 대신
   **항상 top-3 + 점수 구간별 안내 문구**로 판단을 사용자에게 위임하는 쪽을 택했다.

## 근거

- 시드 30건 상태에서 표현 변형(같은 의도를 다르게 묻는 질문) 18건을 추가해 48건으로
  확장한 뒤, 시연 쿼리 3건의 1위 유사도가 다음과 같이 바뀌었다 (`scripts/seeds.json`,
  `static/data/embeddings.json` 재생성 후 실측):

  | 데모 쿼리 | 30건 기준 | 48건 기준 |
  |---|---|---|
  | "인증 토큰 관련해서 궁금한 게 있어요" (demo_queries[0]) | 0.641 | **0.809** |
  | "로그인 처리 어떻게 되어 있나요" (demo_queries[1]) | 0.577 | **0.803** |
  | "이 부분 예전에 누가 담당했는지 알 수 있나요" (demo_queries[2]) | 0.743 | 0.747 |

  표현 변형을 늘릴수록 같은 intent 안에 더 가까운 이웃이 생겨 top-1 점수가 오르는
  경향을 보여준다 (query 0/1처럼 원래 근접 intent 표현이 적었던 쿼리일수록 개선폭이
  큼 — query 2는 애초에 owner-who intent 표현이 이미 촘촘해 개선폭이 작았다).
- 질문+답변을 함께 임베딩하는 방식도 실험했다. 오탐 최고치는 0.730 → 0.576으로
  개선됐으나, 답변까지 포함된 문서 벡터는 한두 문장짜리 실제 사용자 쿼리와 텍스트
  길이가 크게 비대칭이 되어 정작 의미가 가까운 질문을 상위로 끌어올리는 검색 품질
  자체가 떨어졌다. 그래서 **질문(`q`) 단독 임베딩**을 최종 채택했다 (`scripts/build_embeddings.py` 주석 참고).

## 데이터 재생성 완료

이전 리비전에서는 `scripts/seeds.json`이 저장소에 없어 위 실험 결과가 문서상
목표치로만 기록되고, 실제 배포된 `static/data/embeddings.json`은 30건 세트
그대로였다. 이후 `scripts/seeds.json`(48건, `qaSeeds` 배열을 최상위 배열로 정규화)이
추가되고 `static/data/embeddings.json`이 48건 기준으로 재생성되어, 위 표의 수치가
현재 커밋에 그대로 반영돼 있다. `static/data/demo_queries.json`은 쿼리 텍스트가
바뀌지 않아 재생성 대상이 아니며 기존 파일을 그대로 사용한다.
